# RoboFAC のシミュレーションで学習して実機の成否判定を調べる 2026-10-08〜10-09

`docs/2026-10-08-robot-benchmarks.md` で、VSR のアダプタは実機ロボットの成否判定に効かないことが分かった。ここでは、RoboFAC の学習データ (シミュレーション) で QLoRA を行い、**実機の動画の成否判定に転移するか**、入力の工夫と VSR との組み合わせのどれが効くかを、要因を 1 つずつ変えて調べた。スクリプトは `experiments/robot_eval/`、`experiments/finetune/` にある。

## 1. 結論

- **シミュレーションで学習した成否判定は、実機の動画に転移する。** 実機の成否判定 AUC (6 タスクをまとめた値) は、ベース 0.55〜0.65 から **0.84〜0.86** になった (タスクごとの平均では 0.79 から 0.88〜0.93。入力を「最後のフレーム + タスク文」にするだけで、学習なしでもタスク内では 0.79 ある。§6.4)。
- **効いたのは、「最後のフレーム」と「タスク文」の両方を入力にしたときだけ。** どちらか片方だけでは、効かないか弱い (§4.2)。6 フレームのまま学習しても、実機の成否は変わらなかった。
- **VSR で学習した空間判断との両立には、VSR の学習を先にして、あとから RoboFAC で続ける (X8) のが最も良い。** 成否 AUC 0.843、VSR の AUC 0.816 (VSR のみ: 0.838)。同時に混ぜて学習する (X7、X9) と、VSR の力が 0.66〜0.73 までしか保てなかった。
- **RoboSpatial-Home (実室内の空間判断) と VSR は、成否判定の学習で悪化しなかった。**
- **iPhone 上 (QAT Q4_0 + 実行時 LoRA) でも、X8 で成否 AUC 0.628 から 0.777、VSR の AUC 0.63 から 0.79 になった** (§6.1)。
- **最後の 1 枚とタスク文だけで十分で、途中のフレームを入れると悪化する** (§6.2)。時系列は使われていない。
- **失敗の種類は、現時点で、どの設定でも学習できていない。** 最初の学習 (Y1) は、評価と選択肢が違って公平でなかったため、クラスを均等にし、選択肢をランダムにしてやり直した (§6.7)。シミュレーションでの 75.8% (D1) は、**画像ではなく、タスクの種類から決まる癖**だった (タスク名だけの予測で 74.2%)。実機データでの学習 (§6.9) も、損失が当てずっぽうの水準で止まり、毎回同じ答えに潰れた。
- **制約が大きい**: 評価は実機 6 タスクの 602 本 (カメラ above、成功 122 本)、学習は 1 回ずつ。シミュレーションと実機は同じタスクの種類で、**未知のタスクへの汎化ではない** (§5)。

## 2. データと評価

| 項目 | 内容 |
|---|---|
| 学習データ | RoboFAC (MINT-SJTU、MIT) のシミュレーション動画の一部。成功 215 本、失敗 613 本 (成否の設問)、失敗の種類の設問 1,569 本。取得は 2,136 本、1.75 GB。 |
| 学習に使った成否の例 | タスク説明のあるもの: 成功 187、失敗 374 (X2、X4〜X9)。X1・X3 は成功 215、失敗 430 |
| 評価 | 実機の SO-100 アームの動画 (RoboFAC の実機評価分)、カメラ above の 602 本 (成功 122、失敗 480)。成否の AUC を主指標にした。 |
| 保持の確認 | VSR のサンプル 1・2・3 (482 問) の AUC、RoboSpatial-Home「配置」(123 問) の AUC |

入力は、動画から等間隔に取り出したフレーム (評価用に 12 枚から選ぶ)。成否の問いは「作業は成功したか。Yes か No で答える」で、スコアは log p(Yes) − log p(No)。タスク文は、RoboFAC の注釈にある作業の説明 (例: 「Insert the cylinder into the middle hole of the shelf.」) を、プロンプトに「The robot's task is: …」として入れた。

## 3. 学習なしの入力の比較 (QAT ベース、成否 AUC、n=602)

| 入力 | AUC |
|---|---|
| 6 フレーム | 0.550 |
| 最後の 3 フレームのみ | 0.512 |
| 最初と最後の 2 枚 | 0.588 |
| 12 フレーム | 0.559 |
| 6 フレーム + タスク文 | 0.461 |
| **最後の 3 フレーム + タスク文** | **0.645** |

学習しなくても、タスク文と最後の 3 フレームの組み合わせだけは偶然を超えた。

## 4. 学習の結果

学習は QLoRA (QAT 版の土台、rank 16、学習率 1e-4、2 エポック、実効バッチ 16)。成否の答えは「Yes」「No」の 1 トークンで、損失はそこにだけかける。

### 4.1 全実験

| 実験 | 学習データ | 入力 | 実機の成否 AUC | VSR AUC (合計) | RoboSpatial 配置 AUC (通常 / 学習時形式) |
|---|---|---|---|---|---|
| ベース | なし | 6 フレーム / タスク文 + 最後 3 | 0.550 / 0.645 | 0.651 | 0.785 / 0.688 |
| VSR のみ | VSR 5,667 | | (実機 6 フレームで 0.53) | **0.838** | 0.803 / 0.758 |
| X1 | 成否 645 | 6 フレーム | 0.550 | 0.642 | 0.784 / — |
| X3 | X1 + VSR 600 | 6 フレーム | 0.576 | 0.673 | 0.799 / — |
| X4 | 成否 561 | 6 フレーム + タスク文 | 0.666 | 0.651 | 0.789 / — |
| X5 | 成否 561 | 最後 3 フレームのみ | 0.487 | 0.651 | 0.792 / — |
| **X2** | 成否 559 | **最後 3 + タスク文** | **0.845** | 0.649 | 0.801 / — |
| X6 | X2 + VSR 600 | 最後 3 + タスク文 | 0.824 | 0.658 | 0.812 / — |
| X7 | X2 + VSR 3,000 (全文に損失) | 最後 3 + タスク文 | **0.861** | 0.661 | 0.814 / 0.819 |
| X9 | X2 + VSR 3,000 (定型部分は損失なし) | 最後 3 + タスク文 | 0.854 | 0.729 | 0.805 / 0.796 |
| **X8** | VSR のアダプタから続けて X2 のデータ | 最後 3 + タスク文 | **0.843** | **0.816** | 0.773 / 0.745 |

成否 AUC の誤差は、n=602 (成功 122) で ±0.03 程度。0.02 以内の差 (X2、X7、X8、X9) は区別できない。最適閾値での正答率は、X2 が 86.4%、X7 83.6%、X8 84.4%、X9 84.6% (常に「失敗」と答えると 79.7%。閾値を評価データで選ぶので、やや楽観的な値)。

### 4.2 どの要素が効いたか (X1、X2、X4、X5)

| | タスク文なし | タスク文あり |
|---|---|---|
| 6 フレーム | 0.550 (X1) | 0.666 (X4) |
| 最後の 3 フレーム | 0.487 (X5) | **0.845 (X2)** |

「最後の 3 フレームだけ」(X5) は偶然以下、「タスク文だけ」(X4) は弱い効果で、**両方がそろった X2 だけが大きく効く**。ゴール (何をする作業か) と終わった時点の状態を並べて見る形にすると、「そのゴールを達成した状態か」を学習でき、6 フレームの経過を見るだけでは学習が進まなかった。X1 の損失は、成否の事前確率だけで説明できる水準で止まっていた。

### 4.3 VSR との両立 (X6、X7、X8、X9)

- 成否判定の AUC は、VSR を混ぜても落ちない (0.824〜0.861)。
- VSR の力 (0.838) は、混ぜて学習すると保てない: X6 (600 例) 0.658、X7 (3,000 例) 0.661、X9 (3,000 例、定型部分を損失から外した) 0.729。
- **X7 の VSR が低かった一因は、答えの JSON の定型部分 (`{"assessment": "`) にも損失をかけて、学ぶ 1 トークンの重みが薄まったこと。** 定型部分を損失から外すと (X9)、0.661 から 0.729 に上がった。それでも、**順番に学習した X8 (0.816) には及ばない**。混ぜると VSR の学習量が実質的に足りない可能性があるが、原因の切り分けは未実施。
- X8 は、RoboSpatial「配置」が少し下がった (通常 0.773、ベース 0.785、VSR のみ 0.803)。

## 5. 制約と注意

- **同じタスクの種類での、シミュレーションから実機への転移。** 学習 (シミュレーション) と評価 (実機) は、PickCube、PushCube、StackCube、PullCube、PullCubeTool などの同じ系統のタスクを含む。未知のタスクや未知のロボットへの転移は、検証していない。
- 評価はカメラ above の 602 本 (成功 122 本)。rightfront は未評価。誤差は ±0.03 程度。
- 学習は 1 回ずつ (シード固定、ハイパーパラメータの調整なし)。X2 の学習データは、他の実験 (X1、X3) と数が少し違う (559 と 645)。X4・X5 は X2 と同じ集合 (561) で揃えた。
- 入力が「タスク文 + 最後の 3 フレーム」である点は、Supervisor で使う場合、**スキル (FlexBE の状態) の完了時に、その状態の作業の説明と直近のフレームを渡す**使い方に当たる。作業の途中の判断 (周期的な窓、§3) は効かなかった。
- 失敗の種類 (選択式) は、X1〜X9 の学習に含めていない (§6.3 で Y1 として別に学習した)。
- §4 までは bf16 (PC) の結果。iPhone 上 (GGUF、Q4_0、実行時 LoRA) での X8 の測定は §6.1。

## 6. 追加の検証 (10 月 9 日)

### 6.1 iPhone 上の測定 (X8、QAT Q4_0 + 実行時 LoRA)

| | 実機動画の成否 AUC (602 本) | VSR の AUC (S1 / S2 / S3、合計) | 成否 1 本あたり |
|---|---|---|---|
| アダプタなし | 0.628 | 0.622 / 0.605 / 0.671 (0.631) | 4.9 秒 |
| **X8 のアダプタ** | **0.777** | 0.807 / 0.776 / 0.771 (0.787) | 5.9 秒 |
| (参考) bf16、PC | 0.843 | 0.835 / 0.792 / 0.817 (0.816) | |

iPhone 上でも、成否判定と VSR の空間判断が両立した (成否の、タスクごとの AUC の平均は 0.722 から 0.871)。bf16 より成否で 0.066、VSR で 0.03 低いのは、VSR のときと同じく量子化と前処理の差と考えられる (切り分けは未実施)。成否の問い合わせは、3 枚の画像を含めて約 5〜6 秒。

### 6.2 最後のフレームの枚数と間隔 (成否 AUC、n=602)

| 入力 (すべてタスク文あり) | 学習あり (X2 と同じ手順、シミュレーション 561 例) | 学習なし |
|---|---|---|
| 最後の 1 枚 | 0.830 | 0.637 |
| 最後の 2 枚 | 0.834 | 0.597 |
| 最後の 3 枚 (X2) | 0.845 | 0.645 |
| 最後の 6 枚 | 0.825 | 0.554 |
| 途中も含む 4 枚 (5、7、9、11 番目) | 0.725 | 0.505 |

- 1 枚〜6 枚で差はほぼなく (±0.03 の誤差内)、**最後の 1 枚とタスク文だけで十分**だった。成否判定は、「最後の状態がタスクのゴールを満たすか」の静的な判断として学習されていると考えられる。
- **途中のフレームを含めると悪化する** (0.725)。時系列の情報は、この学習では使われていない。
- 学習なしでは、フレームを増やすほど悪化する (0.637 から 0.554)。

### 6.3 失敗の種類 (4 択の設問) を加える

実機の失敗の種類の設問 (3 フレーム、カメラ above の 480 問、選択肢は全問で同じ 3 つ: 向きのずれ 12.5%、つかみの失敗 29%、位置のずれ 58%) の正答率。**偶然は 33% だが、常に「位置のずれ」と答えると 58.3% になる**:

| モデル | 正答率 |
|---|---|
| ベース (QAT、学習なし) | 52.5% |
| X8 (成否だけ学習。失敗の種類は学習していない) | **21.7%** |
| Y1 (X8 の構成 + 失敗の種類 600 例) | 45.8% |

- ~~X8 は、失敗の種類の設問が壊れる~~ (訂正): X8 の正答率 21.7% は、予測が「位置のずれ」から「向きのずれ」に偏りが移っただけで、バランス精度は 37.2% (ベース 32.5%)。**もともと見分けていなかったので、「壊れた」とは言えない**。
- ~~Y1 は、ベースに届かない~~ (訂正): Y1 の学習は、上記のとおり**選択肢が評価と違っており、公平な検証ではない**。バランス精度は 36.3%。結論は保留。
- **ベースの 52.5% (6 フレームでは 55.6%) も、常に「位置のずれ」と答える自明な基準 (58.3%) を下回っている**。つまり、ベースは、失敗の種類をほとんど見分けられていない可能性が高い。これまで「偶然 (33%) を上回る」と書いたのは、基準の取り方が不適切だった。正解の割合の偏りを補正する指標 (たとえばクラスごとの再現率の平均) で見直す必要がある。
- Y1 の成否 AUC は 0.807 (X8: 0.843)、VSR の AUC は 0.821 (X8: 0.816)、RoboSpatial「配置」は 0.772。成否と VSR は X8 に近い水準を保った。

偏りを補正した見方 (クラスごとの再現率、バランス精度 = 3 クラスの再現率の平均。常に C と答えると 33.3%):

| モデル | 正答率 | バランス精度 | 再現率 A / B / C | 予測の内訳 A / B / C |
|---|---|---|---|---|
| ベース、6 フレーム | 54.4% | **32.7%** | 0 / 10 / 88% | 0 / 49 / 431 |
| VSR のアダプタ、6 フレーム | 46.7% | 36.2% | 13 / 36 / 59% | 49 / 153 / 278 |
| ベース、最後 3 フレーム | 52.5% | 32.5% | 3 / 10 / 84% | 11 / 54 / 415 |
| X8 (失敗の種類は学習していない) | 21.7% | 37.2% | 72 / 36 / 4% | 301 / 160 / 19 |
| Y1 (失敗の種類 600 例を加えた) | 45.8% | 36.3% | 38 / 1 / 70% | 149 / 4 / 327 |

- **ベースは、480 問中 431 問で「位置のずれ」と答えており、失敗の種類を見分けていない** (バランス精度 32.7% は偶然と同じ)。正答率 54% は、正解の 58% が位置のずれだからに過ぎない。
- 学習したモデルは、予測が偏る向きが変わるだけで、バランス精度は 36〜37% と偶然 (33%) をわずかに上回る程度 (n=480 の誤差は ±3 ポイント程度なので、有意とは言えない)。
- **したがって、失敗の種類の識別は、ベースは偶然の水準で、学習 (X8、Y1) でも偶然をわずかに上回る程度**。ただし、Y1 の学習は、評価と選択肢が違っていたため、**学習で改善できるかは、Z1・Z2 の結果を待つ**。

### 6.3 の訂正と、影響範囲

失敗の種類の学習は、学習データの**クラスが偏り** (位置のずれ 54%、向き 15%、タイミング 13%、手順の抜け 8%、つかみ 7%、対象物の間違い 4%)、**選択肢が評価と違った** (学習は 6 択で文字が固定: 位置のずれ = F、評価は 3 択で位置のずれ = C) ため、文字や多数派への癖が学ばれ、公平な検証にならなかった。どの実験が影響を受けるかを整理する。

| 実験 | 影響 | 理由 |
|---|---|---|
| X1〜X9、H1、H2 (成否 Yes/No) | **なし** | 選択肢や文字を使わない。答えは Yes/No の 1 トークンで、学習と評価で同じ文面。指標は AUC で、クラス比に左右されない (学習の成功:失敗は 1:2、評価は 1:4。この差は、確率の補正 (§6.6) には影響するが、AUC には影響しない) |
| Y2 (最後のフレームの枚数) | なし | 同上 (成否の Yes/No) |
| iPhone 上の X8 (§6.1) | なし | 成否と VSR (どちらも Yes/No、true/false) |
| VSR の実験 | なし | true/false |
| **Y1 の失敗の種類、X8 の「失敗の種類が壊れる」、VSR のアダプタ後の「悪化」** | **無効 (訂正済み)** | 選択肢の文字の癖と、正解の偏りによる見かけの変化 |
| Y3a、Y3c | 中断 | 同じ不一致を引き継いでいたため止めた |

成否 (Yes/No) の実験に、これと同種の問題はないと考えているが、**次の点は、残る弱さ**: (1) 各実験は 1 回 (シード固定)、(2) 評価は、カメラ above の 602 本 (成功 122 本)、(3) 学習のシミュレーションの成功動画は、別のフォルダ (`success_data`) の動画で、成功らしさの手がかり (カメラの向き、背景) を覚える可能性がある。(3) は、実機の評価で AUC が上がっていること、タスクを除いても効くこと (§6.5) から、主な原因とは考えにくいが、**別のカメラ (rightfront) でも確認する**予定。

この設問は、失敗した動画だけに出る、選択肢が 3 つの分類問題。**失敗の種類の改善の実験は、Z1・Z2 (クラスを均等に、選択肢をランダムに) をやり直している。**

### 6.7 失敗の種類のやり直し (クラス均等、選択肢ランダム、診断)

§6.3 の訂正のとおり、選択肢の不一致とクラスの偏りを直して、学習をやり直した。学習データは、6 クラス (位置のずれ、向きのずれ、タイミング、手順の抜け、つかみ、対象物の間違い) を各 200 例、選択肢は正解を含む 3 つをランダムな順で、6 フレーム。実機の評価は、これまでと同じ 3 択 (480 問)。診断のため、学習に使わないシミュレーションの動画 300 本でも評価した (6 クラス、3 択、偶然 33%)。

| 実験 | 設定 | シミュレーションの hold-out (バランス精度) | 実機 (バランス精度) |
|---|---|---|---|
| ベース | 学習なし | 36.8% (「位置のずれ」ばかり答える) | 32.7% (同上) |
| Z1 | 失敗の種類のみ、1 エポック、学習率 1e-4 (75 ステップ) | — | 33.3% (予測の 98% が「A」) |
| **D1** | 同、2 エポック、学習率 2e-4 (150 ステップ) | **75.8%** (正答率 69%) | **36.9%** (予測は A に偏る) |
| Z2 | VSR のアダプタから + 成否 + 失敗の種類、1 エポック | — | 29.6% |

- **Z1 は、学習が足りなかった**: 損失が最後まで当てずっぽうの水準 (0.549) にとどまった。
- **D1 は、シミュレーションの hold-out で 36.8% から 75.8% になったが、これは画像から失敗の種類を学んだ結果ではない** (§6.7 の訂正を参照)。実機では 36.9% (偶然の水準。ベース 32.7% と差なし)。

- **Z2 は、成否の判定が落ちた**: 実機の成否 AUC は、プール 0.63、タスクごとの平均 0.814 (X8: 0.843、0.905)。VSR は保てた (AUC 0.822)。失敗の種類の例 (1,200) が成否の例 (561) より多く、成否の例は 1 エポックしか見ていない (X8 は 2 エポック) ため、**干渉と学習不足のどちらかは切り分けていない**。実機の失敗の種類は、Z2 でも 29.6% (偶然以下)。

**訂正 (診断)**: D1 のシミュレーションの結果は、**画像を見て失敗の種類を判断した結果ではなかった**。シミュレーションの失敗の種類は、タスクの種類と強く結びついている (例: SpinPullStack は 74% がタイミングの誤り、SafeTask は 73% が位置のずれ)。学習に使わない 300 本で、**画像を見ずにタスク名だけから最頻のクラスを答える予測器**が、正答率 79.7%、バランス精度 74.2% で、D1 (69.0%、75.8%) と同等だった。したがって、「失敗の種類は、シミュレーションでは学習できる」は、**誤り**で、D1 は、タスクとクラスの結びつき (近道) を覚えただけと考えられる。

### 6.9 実機の映像で学習する (失敗の種類)

公開の RoboFAC の実機データ (失敗の 480 エピソード、2 カメラ) を、エピソード単位で学習 60% (288 エピソード・576 本) と評価 40% (192 エピソード・384 本) に分け、クラスを均等に、選択肢を毎回ランダムにして、6 フレームで学習した (学習率 2e-4、2 エポック、72 ステップ)。実機では、タスク名だけの予測は、バランス精度 33.3% で、近道は使えない (各タスクで、位置のずれが 60〜67% を占める)。

| 実験 | 学習 | 評価 (バランス精度、偶然 33%) | 学習の損失 (偶然の水準 0.549) |
|---|---|---|---|
| ベース | なし | 31.7% | |
| D1 (シミュレーションのみ) | | 37.5% | |
| R60s | 実機 60% を最初から | 33.3% (384 本すべて「A」と答える) | 0.549 (25 ステップ以降、変化なし) |
| R60d | D1 から続けて実機 60% | 33.3% (同上) | 0.549 |
| R25s | 実機 15% (72 エピソード) を最初から | 33.3% (同上) | 0.57 |
| R25d | D1 から続けて実機 15% | 33.3% (すべて「C」) | 0.56 |
| L_InsertCylinder | 他 5 タスクの実機、InsertCylinder で評価 | 33.3% (すべて「A」) | 0.549 |

- **実機データの学習は、いずれも、損失が当てずっぽうの水準に張りつき、毎回同じ答えに潰れた**。実機データで学べる信号を、モデルが見つけられていない。**シミュレーションからの転移、少量データの効果、未知タスクへの汎化は、この状態では判定できない** (学習の段階で何も身につかないため。L_StackCube、L_PullCubeByTool は、同じ結果になる見込みで、止めた)。
- 失敗の種類の手がかりを目で確認した (StackCube の例): **最後の 1 枚では、「つかみの失敗」と「位置のずれ」はどちらも「箱が目標に載っていない」状態で、見分けにくい**。違いは、経過の中にある (箱を持ち上げたか、動かしたか)。動作は数フレームの間に起き、箱は小さいので、**等間隔の 6 枚 (1 枚 280 トークン) では、手がかりが見えにくい**可能性がある。
- 成否の判定 (最後の状態 + タスク文) が効いたのとは対照的に、**失敗の種類は、最後の状態ではなく、経過 (動き) を見る必要があるタスクと考えられる**。
- **今後の方針案**: 経過を見せる入力 (動作の途中のフレームを密に、または解像度を上げる)、失敗の種類の定義をタスクごとに見直す (PushCube に「つかみの失敗」がある、など、ラベルの意味が曖昧)、あるいは、失敗の種類は当面扱わず、成否判定と理由の文章に絞る。

| | プール AUC | タスクごとの平均 |
|---|---|---|
| ベース (学習なし) | 0.666 | 0.746 |
| X2 | 0.808 | 0.889 |
| X8 | 0.813 | 0.882 |

別のカメラでも、**ベースより約 0.14 上がる** (プール)。上昇幅は、カメラ above (0.645 から 0.845) より少し小さいが、傾向は同じで、タスクを除いた学習 (H1、H2) でも保たれる。**特定のカメラの手がかりを覚えているだけ、という見方は否定された** (同じエピソードなので、完全に独立した検証ではない)。

### 6.4 タスクごとの AUC (訂正を含む)

これまでの成否 AUC は、6 つのタスクの動画を**まとめて**順位づけした値 (プール AUC)。タスクごとに成功率とスコアの水準が違うため、プール AUC は、**タスクをまたいだスコアの揃い方**にも左右される。タスクごとの AUC (各タスクの成功と失敗だけを比べる) と、その 6 タスクの平均を並べる。

| 実験 | プール AUC | タスクごとの平均 | Insert | PickInBox | PullCube | PullTool | Push | Stack |
|---|---|---|---|---|---|---|---|---|
| ベース、6 フレーム | 0.550 | 0.517 | 0.79 | 0.23 | 0.56 | 0.35 | 0.63 | 0.54 |
| ベース、最後 3 のみ | 0.512 | 0.506 | 0.63 | 0.30 | 0.53 | 0.35 | 0.84 | 0.38 |
| ベース、6 フレーム + タスク文 | 0.461 | 0.556 | 0.79 | 0.47 | 0.55 | 0.44 | 0.55 | 0.53 |
| **ベース、最後 3 + タスク文** | **0.645** | **0.794** | 0.82 | 0.86 | 0.66 | 0.80 | 0.82 | 0.81 |
| X1 (6 フレーム、学習) | 0.550 | 0.557 | 0.66 | 0.58 | 0.42 | 0.30 | 0.79 | 0.59 |
| X5 (最後 3 のみ、学習) | 0.487 | 0.468 | 0.43 | 0.49 | 0.56 | 0.21 | 0.80 | 0.33 |
| X2 (最後 3 + タスク文、学習) | 0.845 | 0.882 | 0.86 | 1.00 | 0.69 | 0.82 | 0.97 | 0.96 |
| X7 | 0.861 | 0.930 | 0.85 | 1.00 | 0.87 | 0.97 | 0.98 | 0.92 |
| X8 | 0.843 | 0.905 | 0.87 | 1.00 | 0.72 | 0.97 | 0.95 | 0.92 |
| X9 | 0.854 | 0.908 | 0.89 | 1.00 | 0.78 | 0.95 | 0.98 | 0.85 |
| Y1 | 0.807 | 0.879 | 0.83 | 1.00 | 0.83 | 0.89 | 0.93 | 0.79 |

- **訂正**: 本文で「学習なしでは偶然並み」「学習して初めて効く」と書いた部分は、**入力が「最後の 3 フレーム + タスク文」のベースには当てはまらない**。この入力なら、学習なしのベースでも、タスクの中では成否を平均 AUC 0.79 で見分けている (6 フレームでは 0.52)。プール AUC が 0.645 と低かったのは、タスクごとのスコアの水準が揃っていなかったため。
- 学習の効果は 2 つ: タスク内の AUC が 0.79 から 0.88〜0.93 に上がる (+0.09〜0.14) ことと、**タスクをまたいでスコアの水準が揃い、プール AUC が 0.645 から 0.85 になる**こと。後者は、1 つのしきい値で全タスクを判定したいときに効く。
- 入力の効果は、タスクごとの AUC で見ると一層はっきりする: 6 フレームや「最後のフレームのみ」の入力は、学習しても、タスクごとの平均が 0.5 前後。
- **シミュレーションに対応するタスクがあるものは大きく向上する** (PickInBox 0.86 から 1.00、Push 0.82 から 0.97、Stack 0.81 から 0.96)。対応がない InsertCylinder は +0.04〜0.07 にとどまる (ベースが 0.82 と、すでに高い)。PullCube は、学習データの差で 0.69〜0.87 と大きくばらつく。タスクごとの件数は 120 本前後 (成功は 20 本) と少なく、タスクごとの AUC の誤差は ±0.1 程度ある。

### 6.5 未知タスクへの汎化 (学習から除いたタスク)

学習のシミュレーションデータから、あるタスク系統を除いて (X2 と同じ手順で) 学習し、実機のそのタスクで成否の AUC (タスクごと) を見た。H1 は PickCube、StackCube、PushCube を除外 (実機: PickCubeInBox、Push、Stack で評価)、H2 は PullCube、PullCubeTool を除外 (実機: PullCube、PullCubeByTool で評価)。

| | PickCubeInBox | PushCube | StackCube | PullCube | PullCubeByTool | InsertCylinder | プール |
|---|---|---|---|---|---|---|---|
| ベース (学習なし) | 0.86 | 0.82 | 0.81 | 0.66 | 0.80 | 0.82 | 0.645 |
| X2 (全タスクで学習) | 1.00 | 0.97 | 0.96 | 0.69 | 0.82 | 0.86 | 0.845 |
| **H1 (Pick/Stack/Push を除いて学習)** | **1.00** | **0.95** | **0.96** | 0.82 | 0.81 | 0.85 | 0.816 |
| **H2 (PullCube/PullCubeTool を除いて学習)** | 1.00 | 0.95 | 0.96 | **0.81** | **0.83** | 0.83 | 0.835 |

- **除いたタスクでも、向上は変わらなかった**: H1 の PickInBox、Push、Stack は、除かなかった X2 とほぼ同じ (1.00、0.95、0.96)。H2 の PullCube、PullCubeByTool は X2 と同等かそれ以上。**学習で身についたのは、特定のタスクの見分け方ではなく、「最後の状態がタスク文の目標を満たしているか」を見る一般的な力**と考えられる。
- 実機の InsertCylinder は、どの学習にも対応するシミュレーションのタスクがないが、ベース 0.82 から 0.83〜0.89 と、わずかに上がるだけ (ベースがすでに高く、向上の余地が小さい)。
- **制約**: 評価したのは、ピック、プッシュ、スタック、プルといった、似た系統の 6 タスクと、同じ SO-100 アーム。学習から除いたのは、シミュレーション側の同名のタスクだけで、**他のロボットや、まったく別の種類の作業 (扉を開ける、道具を使うなど) への汎化は、確認できていない**。タスクごとの件数が少なく (成功 20 本前後)、タスクごとの AUC の誤差は ±0.1 程度。

### 6.6 スコアの信頼性 (キャリブレーション)

スコアは log p(Yes) − log p(No)。これを確率 p = sigmoid(スコア) に直して、実際の成功率と比べた (成功 122、失敗 480 本。カメラ above)。ECE (確率のずれの平均、小さいほど良い)、Brier スコア (0 に近いほど良い。常に「失敗」の確率 0.2 を返す基準は 0.162)。

| 実験 | そのまま sigmoid: ECE / Brier | 全タスクで補正 (2 分割で検証): ECE / Brier | タスクごとに補正 (各タスクの半分で補正し残りで検証): ECE / Brier |
|---|---|---|---|
| ベース (最後 3 + タスク文) | 0.115 / 0.170 | 0.019 / 0.156 | 0.038 / 0.149 |
| X2 | 0.053 / 0.113 | 0.031 / 0.110 | 0.031 / 0.097 |
| X8 | 0.048 / 0.116 | 0.035 / 0.116 | 0.017 / 0.093 |
| X9 | 0.069 / 0.121 | 0.053 / 0.114 | 0.029 / 0.090 |

- 学習前は、そのままの確率は信用できない (ECE 0.115、Brier は基準以下)。**学習後は、そのままでもずれが小さい** (ECE 0.05)。
- **タスク (State) ごとの補正をかけると、Brier が 0.09〜0.10 になり、基準 (0.162) を大きく下回る**。補正には、1 タスクあたり約 60 本 (成功 10 本前後) を使った。
- 生成した文の中の数字 (「confidence: 0.9」と言わせる形) は、**測っていない**。小さなモデルの自己申告は信頼できないと考えられるので、使わず、スコアから補正した確率を使う設計にする。

## 7. 次の候補

1. 失敗の種類を改善する。実機の失敗の種類の例が必要 (自前の実機映像で、少量でもラベルを付けて学習と評価に使う)。シミュレーション側の例を増やす (今回は 600 例) 方法は、先に試す価値がある。
2. 成否判定の入力は「最後の 1〜3 フレーム + タスク文」で十分なので、**Supervisor の使い方 (スキルの完了時に作業の説明と直近のフレームを渡す)** に合わせて、アプリとの連携を設計する。
3. 学習のばらつき (シード、エポック数) を調べる。
4. 未知のタスク、未知のロボットへの汎化を調べる (学習に含めないタスクを決めて評価する)。
5. 同時に混ぜる学習 (X9) を、VSR の量や比率を変えて調べる。順番に学習する X8 に迫れるか。
6. iPhone と bf16 の差の原因を切り分ける。
