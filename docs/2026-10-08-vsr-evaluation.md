# 空間関係の判定精度の評価 (VSR) とファインチューニング 2026-10-05〜10-08

ロボットの上位判断 (VLM Supervisor) に使えるか、という観点で、iPhone 16 上のマルチモーダルモデルの「画像の空間関係を判定する力」を測り、Gemma 4 E2B を改良した記録。再現用のスクリプトは `experiments/` にある。

## 1. 結論

- **素の Gemma 4 E2B は、空間関係の判定が弱い。** Qwen3-VL-4B に 73.3% 対 55.8% (サンプル1) で負け、特に左右の区別がほぼ偶然だった。原因は「true と答えにくい癖」だけではなく、視覚的な弁別力そのものだった (§4.1)。
- **ファインチューニング (QLoRA、VSR の学習データ 5,667 問、約 1 時間) で、1 回の問い合わせ (約 2 秒) のまま Qwen3-VL と同等以上になった。** iPhone 上での精度は、AUC が 0.631 から 0.794、正答率が 57.3% から 72.6% に上がった (サンプル 1〜3 の合計 482 問)。
- **iPhone への載せ方は、「公式の QAT Q4_0 に LoRA アダプタを実行時に重ねる」方式が最良。** 微調整した重みをマージして Q4_0 に量子化し直す方式は、効果が量子化の誤差に埋もれて大きく劣った (AUC 0.703)。アダプタは 48 MB。
- **学習は QAT 版の重みを土台にする方が良い。** 通常版を土台にした場合より、iPhone で AUC が 0.757 から 0.794 に上がった。
- **過学習の兆候は見られず、別の領域にも効果が移る。** 学習で見た画像と見ていない画像で精度が同じ。学習から除いた関係でも効果の約 8 割が移り、写真ではない図形の合成画像でも上がった (§4.5)。
- **thinking を使わなくてよい。** FT 後は thinking を付けても AUC が +0.03 程度しか上がらず、時間は約 8 倍 (17〜18 秒)。
- **未検証:** ロボットの実画像での効果、FT と 2 段階プロンプトの併用、アプリの設定画面からのアダプタ選択 (今は起動引数のみ)。

## 2. 評価の方法

### 2.1 データ

VSR (Visual Spatial Reasoning, Liu et al., TACL 2023, CC BY 4.0)。画像は COCO (CC BY 2.0)。「The cat is to the left of the dog.」のような文が画像に対して正しいかを判定する。

| 名前 | 内容 | 件数 |
|---|---|---|
| sample1 | ランダム分割の test から、検証者の票が全員一致の問題を 14 の関係 × 真偽 × 6 問 (シード 11) | 165 |
| sample2 | sample1 と重ならない同じ構成 (シード 7) | 162 |
| sample3 | sample1・2 と重ならない同じ構成 (シード 21)。方式を選ぶ間は使わず、最終比較にだけ使った | 155 |
| seen | 学習に使った問題 (学習済みの画像) | 165 |
| shapes | 白地に色付きの図形 2 つを描いた合成画像。左右上下を問う | 240 |
| train | ランダム分割の train のうち、test に出る画像を除いたもの。学習に使用 | 5,667 |

ランダム分割は train と test で 978 枚の画像を共有する。そのまま学習すると、見た画像でテストすることになるので除外した。

### 2.2 指標

- 各問で、モデルが答えを書く位置の log p("true") − log p("false") を記録する (アプリの `logprobs` を使用)。
- **ROC-AUC**: この値で true と false の問題をどれだけ分けられるか (0.5 が偶然、1.0 が完全)。「true と答える癖」に左右されない。
- **正答率 (own)**: 値 > 0 で true と答えたとして計算。
- n=160 前後のとき、AUC の誤差は ±0.04 程度。差が 0.05 未満の違いは区別できない。
- プロンプト (`experiments/vsr/probe.py`): システム「Look at the image and decide whether the statement about it is true. Answer with JSON only: {"assessment": "true" | "false"}.」、ユーザー「Statement: …」+ 画像。温度 0、出力上限 24 トークン (thinking オンは 3000)。

### 2.3 実機

iPhone 16 (8 GB)、llama.cpp b10456 (Metal)、画像トークンは既定 (Gemma 4 は最大 280)。PC 側の bf16 評価は RTX 5060 Ti (16 GB)。Gemma 4 E2B の QAT Q4_0 は Google 公式 (`google/gemma-4-E2B-it-qat-q4_0-gguf`)。

## 3. 結果

### 3.1 iPhone、thinking オフ (サンプル 1・2・3)

| 方式 | AUC (S1 / S2 / S3) | AUC 合計 | 正答率 | 1問あたり |
|---|---|---|---|---|
| QAT Q4_0 そのまま | 0.622 / 0.605 / 0.671 | 0.631 | 57.3% | 1.8 秒 |
| 通常版を土台に FT → マージ → Q4_0 | 0.778 / 0.683 / — | 0.732 (S1・2) | 64.8% | 2.0 秒 |
| 通常版を土台に FT → アダプタを実行時 LoRA | 0.767 / 0.727 / 0.774 | 0.757 | 68.7% | 2.1 秒 |
| QAT 版を土台に FT → マージ → Q4_0 | 0.710 / 0.672 / 0.733 | 0.703 | 61.0% | 1.9 秒 |
| **QAT 版を土台に FT → アダプタを実行時 LoRA** | **0.837 / 0.769 / 0.776** | **0.794** | **72.6%** | 2.1 秒 |

(参考) 他モデル、サンプル 1 / 2: Qwen3-VL-4B Q4_K_M は AUC 0.785 / 0.722、正答率 73.3% / 66.0%、1 問 5.4〜5.7 秒。

### 3.2 iPhone、thinking オン (サンプル3、出力上限 3000 トークン)

| 方式 | thinking オフ AUC | thinking オン AUC | オン時の正答率 | 1問あたり | 生成トークン |
|---|---|---|---|---|---|
| QAT そのまま | 0.671 | 0.743 | 73.5% | 17.7 秒 | 248 |
| 通常版土台 FT + 実行時 LoRA | 0.774 | 0.791 | 74.2% | 16.3 秒 | 208 |
| QAT 土台 FT + 実行時 LoRA | 0.776 | 0.803 | 73.5% | 17.5 秒 | 218 |
| QAT 土台 FT + マージ | 0.733 | 0.762 | 72.3% | 17.6 秒 | 239 |

thinking は素のモデルには効く (AUC +0.07) が、FT 後はほとんど上積みがない。FT 後の thinking オフ (正答率 72.9%、2.3 秒) が、素のモデルの thinking オン (73.5%、17.7 秒) と同等で、8 倍速い。

別の実行 (S1 / S2、生データは PC の再起動で失われたため記録した数値): QAT そのままで thinking オン AUC 0.751 / 0.756、正答率 69.1% / 71.6%、1 問 18.1 / 20.6 秒。

### 3.3 入力の工夫 (FT なし、QAT そのまま、サンプル 1 / 2 の AUC)

| 方式 | S1 | S2 | 1問あたり |
|---|---|---|---|
| 基準 | 0.622 | 0.605 | 約 2 秒 |
| 質問形に言い換え | 0.654 | — | 約 2.3 秒 |
| 画像トークンを 560 に拡大 | 0.702 | — | 約 12 秒 |
| 座標で位置を出させてから判定 (2 段階) | 0.615 | 0.560 | — |
| 左右上下を型で答えさせてから判定 (2 段階) | 0.677 | 0.677 | — |
| **自由な言葉で位置を説明させてから判定 (2 段階)** | **0.780** | **0.689** | 約 6.8 秒 |

- 2 段階は、1 回目で「画像のどこに物体があるか」を言葉にさせ、2 回目でそれを文脈に判定する。サンプル 1 の効果はサンプル 2 より大きく、サンプル 1 は良く出た面がある。
- 画像トークン 1120 は、LLM の計算バッファが 1.26 GB に膨らんでアプリがメモリ不足で落ちた。
- これらの生データも再起動で失われ、数値は記録による。

### 3.4 PC の bf16 (サンプル 1 / 2 / 3 の AUC)

| モデル | S1 | S2 | S3 | 合計 AUC | 正答率 |
|---|---|---|---|---|---|
| 通常版 | 0.648 | 0.559 | 0.683 | 0.630 | 50.6% |
| QAT 版 | 0.652 | 0.614 | 0.690 | 0.651 | 57.7% |
| 通常版土台 FT | 0.851 | 0.769 | 0.806 | 0.810 | 72.0% |
| QAT 版土台 FT | 0.872 | 0.808 | 0.832 | 0.838 | 76.6% |

iPhone 上の値は bf16 より 0.04〜0.06 低い。量子化と画像の前処理の違いによると考えられるが、切り分けは未実施。

## 4. 考察

### 4.1 Gemma 4 の弱さの原因

- 画像なしで同じ文を判定させると AUC は 0.512 (偶然)。画像は使われているが、手がかりとして弱い (AUC 0.62)。
- 「true と答えにくい癖」はある (true 文の 21% しか true と答えない)。閾値を最適化しても正答率は 64.2% にしか上がらず、Qwen の 75.2% に届かない。癖だけでは説明できない。
- 関係別では **左右** が最も弱い (AUC 0.51。Qwen は 0.86)。

### 4.2 FT が効いた理由

- 2 段階プロンプトや thinking と同様に、「画像の位置を判断に結びつける」手順を補う効果が出たと見られる。FT 後は左右の AUC が 0.51 から 0.76〜0.87 に上がり、真偽の偏りも解消した (true と答える割合 4% → 約 50%)。
- 学習は 1 回の問い合わせのまま行うため、推論時間は増えない。

### 4.3 マージより実行時 LoRA が良い理由

LoRA の差分は小さい。マージして Q4_0 に量子化し直すと、4 ビットの丸め誤差に埋もれて効果が弱まる。公式 QAT の量子化済みの重みに、16 ビットの差分を実行時に足す方式は、差分が丸められない。

### 4.4 QAT 版を土台にする理由

通常版を土台にして学習した差分は、QAT で量子化に合わせて調整された重みの上では、効果が減る。QAT 版を土台にすると、実際に使う重み (QAT Q4_0) と学習時の重みが近くなる。

### 4.5 汎化性の確認 (PC の bf16)

| 確認 | 通常版 | 通常版土台 FT | QAT 版土台 FT |
|---|---|---|---|
| 学習した画像 (seen) の AUC | 0.625 | 0.816 | 0.867 |
| 見ていない画像 (S1〜3 合計) の AUC | 0.630 | 0.810 | 0.838 |
| 図形の合成画像 (shapes) の AUC | 0.684 | 0.804 | 0.853 |

- 学習した画像と見ていない画像で AUC がほぼ同じなので、暗記ではない。学習の損失は 0.18 まで下がったが、評価の差は出ていない (むしろ学習不足の可能性がある)。
- 図形は写真と全く異なる領域だが、効果が出た。「右」と「下」は素のモデルでは偶然並み (AUC 0.45 前後) だったのが、FT 後は右 0.97、下 0.65 になった。
- **関係を学習から除く検証**: 「左」「右」「上」「下」の 4 関係を学習から除いて同じ条件で学習し、全サンプル (482 問) でその 4 関係 (144 問) を評価した。AUC は、素のモデル 0.506、除いた学習 0.682、全関係で学習 0.728。学習で見ていない関係でも、効果の約 8 割が移った。

## 5. その他の調査

### 5.1 コミュニティのモデル

- **Hugging Face の gemma-challenge (Fast Gemma Challenge)**: GPU サーバー (a10g-small) で `google/gemma-4-E4B-it` のテキスト生成速度 (TPS) を、エージェントが競うもの。画像や iPhone とは直接関係がなかった。
- **Hub の Gemma 4 E2B 派生**: 検閲解除版、言語別の SFT、テキストのみの推論蒸留が中心。空間認識の視覚に特化したものは見つからなかった。
- **Claude Sonnet 4.6 蒸留 (Blshu、Q6_K)** を実測した。サンプル 1 の AUC は 0.625 で QAT 版 (0.622) と同じ。1 問 4.0 秒と遅く、2 段階の途中でメモリ不足で落ちた。テキストの蒸留では視覚は変わらない。採用しなかった。

### 5.2 Google 公式の周辺

- `-assistant` は MTP (Multi-Token Prediction) のドラフターで、投機的デコーディングにより最大 3 倍の高速化とされる。llama.cpp 本体は対応しているが、アプリが使う C API には公開されておらず (上流 issue #27788)、使うには自前の実装が必要。thinking の速度改善には有望で、保留している。
- `qat-mobile` は LiteRT 向け。LiteRT は iOS で画像が使えないため対象外。
- 12B は iPhone のメモリに載らない。

## 6. 学習と変換の手順

- 学習: QLoRA (4 ビット NF4)、rank 16、alpha 32、dropout 0.05、学習率 1e-4 (線形減衰)、1 エポック、実効バッチ 16、言語モデルの全ての線形層に LoRA (24M パラメータ、全体の 0.47%)。答えのトークンだけに損失を付ける。ビジョン・オーディオは固定。RTX 5060 Ti で約 61 分、メモリのピークは 13.1 GB。
- `prepare_model_for_kbit_training` は使わない: 全重みを fp32 に変換し、Per-Layer Embeddings (47 億パラメータ) で 8.75 GB を要求して GPU に載らない。
- アダプタの変換: llama.cpp の `convert_lora_to_gguf.py` (`--base` に HF の QAT 版)。`gguf` だけを入れる (変換スクリプトの requirements は transformers を古い版に下げ、トークナイザの設定が読めなくなる)。
- アプリ側: 起動引数 `-llamaLoraPath FILE` (モデルのフォルダからの相対パス)、`-llamaLoraScale S`。画像トークンは `-llamaImageMinTokens` / `-llamaImageMaxTokens`。

## 7. 制約と注意

- **評価は VSR (COCO の写真) と合成図形だけ。** ロボットの実画像、ロボットが実際に問う判断 (回復行動の選択など) での効果は未検証。
- サンプルは 160 問前後で、AUC の誤差は ±0.04 程度。サンプル 1 は方式を選ぶ間に何度も見ており、2 段階の効果が大きく出た一因と思われる。サンプル 3 は最終比較まで使わなかった。
- 学習は 1 回だけ (シード固定、ハイパーパラメータの調整なし)。再現性 (シードによるばらつき) は未確認。
- 一部の生データ (2 段階、thinking の S1・S2、Qwen の S2、座標方式など) は PC の再起動で失われ、数値は実行時の記録による。`experiments/` のスクリプトで再現できる。
- iPhone では bf16 より AUC が 0.04〜0.06 低い。原因 (量子化か前処理か) は未切り分け。
- メモリ: 8 GB の iPhone では 3.8 GB のモデル (Q6_K) や画像トークン 1120 でアプリが落ちる。

## 8. 次の候補

1. アプリの設定画面からアダプタを選べるようにする (今は起動引数のみ)。
2. ロボットが実際に問う判断の種類を決め、その画像と判断例で学習する。
3. FT と 2 段階プロンプトの併用を測る。
4. 学習のシード・エポック数・rank のばらつきを調べる。
5. iPhone と bf16 の差の原因を切り分ける (PC 上の llama.cpp で f16 と Q4_0 を比較)。
6. MTP ドラフターを使った投機的デコーディングを自前で実装する。

## 9. 再現手順

```bash
python3 experiments/vsr/prepare.py                  # データ取得 (既定 ~/data/vsr)。画像は使用後に削除する
python3 experiments/vsr/prepare_generalization.py   # seen / sample3 / shapes
docker build -t vlm-finetune:dev experiments/finetune
# 学習 (QAT 版の HF 重みを ~/models/hf/gemma-4-E2B-it-qat に置く)
docker run --rm --gpus all -v ~/models:/models -v ~/data:/data -v $PWD/experiments/finetune:/work \
  vlm-finetune:dev python train_lora.py --model /models/hf/gemma-4-E2B-it-qat --data /data/vsr/train --out /data/vsr/adapters/ft_qat
# 変換と iPhone での測定は experiments/vsr/pipeline_qat.sh を参照
python3 experiments/vsr/probe.py MODEL OUT.json --data ~/data/vsr/sample1
python3 experiments/vsr/analyse.py OUT.json
```
